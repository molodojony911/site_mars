# MARS Agency — Design Documentation

Визуальный макет лендинга [mars-agency.pro](https://mars-agency.pro) для репозитория `site_mars`.

**Прототип:** `design/index.html` — откройте в браузере или через локальный сервер.

---

## 1. Цели дизайна

| Цель | Решение |
|------|---------|
| Конверсия в заявку | CTA в hero → две формы лид-магнита, sticky header, повторный CTA-блок |
| Доверие | Метрики (500+ проектов, +35% конверсии), блок партнёров, FAQ |
| Понятность услуг | 4 карточки услуг с bullet-списками |
| Премиальный HoReCa-образ | Тёмный hero с 3D-сценой, красный акцент, Montserrat, минимализм |
| Сегментация лидов | Две формы: аудит сайта и проверка бронирования/меню |

## 3. Hero 3D-сцена (Three.js)

**Файлы:** `design/js/hero-3d.js`, Three.js r128 через CDN.

| Элемент | Описание |
|---------|----------|
| Ядро | Icosahedron с emissive-подсветкой и wireframe-оболочкой |
| Кольцо | Torus вокруг ядра, красный акцент `#E02121` |
| Частицы | Point cloud (~120 mobile / ~220 desktop) |
| Освещение | Ambient + directional + красный point light |

### Поведение и доступность

- **`prefers-reduced-motion: reduce`** — один статичный кадр, без `requestAnimationFrame`.
- **WebGL недоступен / ошибка** — CSS fallback с radial-gradient (класс `hero__canvas-wrap--fallback`).
- **Canvas** помечен `aria-hidden="true"` — декоративный элемент, не мешает screen readers.
- **Производительность:** меньше частиц и pixel ratio на coarse pointer (touch).

## 4. Лид-магниты (UX)

### Форма 1: Аудит сайта (`#leads-audit`)

| Поле | Назначение |
|------|------------|
| URL сайта | Точка входа для экспертизы |
| Имя | Персонализация ответа |
| Телефон | Основной канал связи в HoReCa |
| Согласие | GDPR/152-ФЗ compliance |

**CTA:** «Получить аудит» — конкретное обещание ценности.

### Форма 2: Проверка бронирования и меню (`#leads-booking`)

| Поле | Назначение |
|------|------------|
| Название ресторана | Идентификация заведения |
| Ссылка на меню/бронь | Контекст для проверки |
| Телефон | Обратная связь |
| Чекбоксы фокуса | Сегментация запроса (бронь / меню / доставка) |
| Согласие | Юридическое требование |

**CTA:** «Заказать проверку» — отличается от аудита, снижает путаницу.

### UX-решения

1. **Две отдельные карточки** вместо табов — обе формы видны на desktop без лишних кликов.
2. **`scroll-margin-top`** на карточках — якорные ссылки из hero не прячутся под sticky header.
3. **Hero CTA** ведут напрямую к нужной форме (`#leads-audit`, `#leads-booking`).
4. **Контакты** дублируют CTA для пользователей, предпочитающих звонок/мессенджер.
5. **Минимум обязательных полей** — снижение friction; опциональные чекбоксы фокуса только во второй форме.

## 6. Типографика

- **Шрифт:** Montserrat (Google Fonts) — аналог Mont с текущего сайта
- **Hero H1:** `clamp(2rem, 5vw + 1rem, 3.75rem)`, weight 700
- **Section H2:** 1.875rem → 2.25rem на tablet+
- **Body:** 1rem / line-height 1.55
- **Eyebrow:** uppercase, letter-spacing 0.04em, красный

## 7. UX-заметки

### Навигация

- Sticky header сохраняет доступ к CTA и телефону при скролле.
- На mobile — drawer справа с backdrop; закрытие по Escape, клику на backdrop или переходу по ссылке.
- Skip-link «Перейти к содержимому» для screen readers и клавиатуры.

### Конверсионные точки

1. Hero CTA → лид-магниты (аудит / бронирование)
2. Header кнопка «Оставить заявку» → `#contact`
3. CTA banner в середине страницы
4. Две формы лид-магнита в секции `#leads`
5. Повторные CTA в блоке контактов

**Рекомендация для продакшена:** добавить плавающую кнопку WhatsApp/Telegram на mobile.

### Формы

- Inline-валидация с `aria-invalid` и сообщениями об ошибках.
- URL-поля проверяются на корректность hostname.
- После отправки — `role="status"` + programmatic focus для screen reader.
- Разные `aria-label` на формах для однозначной идентификации.

### FAQ

- Аккордеон: один открытый пункт за раз (снижает когнитивную нагрузку).
- `aria-expanded`, `aria-controls`, `role="region"` для доступности.

### Контент

- Pain tags визуализируют боли ЦА — владельцы ресторанов узнают себя.
- Процесс «Анализ → Стратегия → Рост» снимает страх «непонятного агентства».
- Плейсхолдеры партнёров — заменить реальными логотипами при интеграции.

## 8. Доступность (WCAG 2.1 AA)

| Критерий | Реализация |
|----------|------------|
| 1.3.1 Info and Relationships | Семантика: `header`, `nav`, `main`, `section`, `article`, `fieldset`, `legend` |
| 1.4.3 Contrast | Палитра проверена (см. таблицу выше) |
| 2.1.1 Keyboard | Все интерактивные элементы доступны с клавиатуры |
| 2.3.3 Animation from Interactions | 3D-анимация отключается при `prefers-reduced-motion` |
| 2.4.1 Bypass Blocks | Skip-link |
| 2.4.7 Focus Visible | `:focus-visible` с синим outline 3px |
| 3.3.1 Error Identification | `aria-invalid` + текст ошибки |
| 3.3.2 Labels or Instructions | `<label>` для каждого поля, `legend` для группы чекбоксов |
| 4.1.2 Name, Role, Value | ARIA на меню, FAQ, формах, соцсетях |

**Дополнительно для продакшена:**

- Реальные alt-тексты для логотипов партнёров.
- Модальные окна политики конфиденциальности с focus trap.
- Lazy-load Three.js только при видимости hero (Intersection Observer).
